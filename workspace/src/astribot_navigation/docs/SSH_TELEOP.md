# S1 SSH 键盘遥操

在 S1 上执行，无需编译 ROS 工作区：

```bash
cd /home/astribot/TowerGO/workspace/src/astribot_navigation
./scripts/tg-teleop.sh --dry-run
./scripts/tg-teleop.sh
```

从电脑直接进入：

```bash
ssh -t S1 '/home/astribot/TowerGO/workspace/src/astribot_navigation/scripts/tg-teleop.sh'
```

| 按键 | 功能 |
|---|---|
| W / S | 沿底盘当前朝向前进 / 后退 |
| Q / E | 原地左转（逆时针）/ 右转（顺时针） |
| A / D | 沿底盘当前朝向左横移 / 右横移 |
| 空格 | 冻结最后目标 |
| + / - | 同时提高 / 降低速度一档；普通键盘 = 也可加速 |
| X / Ctrl+C | 退出；Q 不是退出键 |

大小写均可。每个方向字符有效 0.2 秒，持续按键重复可续期；松手后不再收到字符则冻结目标。终端不提供真实松键事件，首次长按到开始自动重复之间可能短暂停顿。本版支持单方向前后、横移或转向，不支持组合方向运动或一次按键永久行驶。同批输入停止/退出优先，多个方向只取最后一个，不保存动作队列。未知字符（包括方向箭头）停止积分；请使用表内字母。调速不会延长运动有效期。

默认线速度 0.05 m/s、角速度 0.10 rad/s。前后与横移共用线速度，范围 0.01–1.0 m/s，每档 0.01；角速度范围 0.025–0.25 rad/s，每档 0.025。可指定初值：

```bash
./scripts/tg-teleop.sh --linear-speed 0.03 --angular-speed 0.075
```

## 控制行为

真机入口采用厂商 202 示例的局部累计指令定义：以 100 Hz 固定步长直接积分局部 x、y 和 yaw：W/S 仅改变 x，A/D 仅改变 y，Q/E 仅改变 yaw，不根据 yaw 额外旋转速度。只给底盘发送目标（明确关闭默认躯干目标和 WBC）。延迟后不补发积压帧；超过 0.1 秒的周期停顿退出。已有 ROS keyboard/chassis 入口与其硬件验证配置不变；本工具的目标保持停车方式不表示已有硬件验证合同已通过。

2026-10-08 坐标定义复核：旧版本错误地把局部累计目标当作世界坐标，对 W/S 额外乘以 yaw 的旋转矩阵。这会引入横向指令，并随 yaw 改变正负方向；随后仅反转平移符号的修补也不成立，现已撤销。当前 W 为局部 x 正增量，S 为负增量，Q/E 分别为 yaw 正/负增量。状态行标为 local_cmd，不表示世界系位姿。

核查依据（S1 本地）：

- `/home/astribot/astribot_sdk_aarch64/examples/202-chassis_joy_control_local.py`：局部速度直接累加到三项位置指令。
- `/home/astribot/astribot_sdk_aarch64/examples/203-chassis_joy_control_global.py`：全局控制时先用 `rot_mat.T @ vel` 把全局速度变为局部速度，再以相同方式累加。这与旧版遥操中反向的转换假设冲突。
- `/home/astribot/astribot_sdk_aarch64/astribot_config/robot_config/astribot_s1/astribot_chassis.yaml`：三项顺序为 x、y、z_rot，配置频率 100 Hz。
- 既有 `workspace/data/reports/hardware_interface_review_20260923/control_findings.md` 同样记录这些值不能直接当标准世界坐标里程计。

主目录 tg-chassis 仍保留旧的世界坐标假设，本次未修改该独立工具；不要将它的行为作为本入口的坐标定义。旧 ROS 键盘入口仍使用 A/D 转向、Q 退出，也不要混用按键说明。底层驱动包含编译库，源码一致性测试不能替代修正后的实车方向验收。

遥操期间关闭终端 XON/XOFF 流控，避免 Ctrl+S 暂停输出；Ctrl+S/Ctrl+Q 作为未知字符停止当前积分，退出后恢复原终端设置。冲突检测覆盖官方 202/203 手柄示例及其他真机遥操进程（包括锁目录不同的实例），仍不构成对所有外部控制器的强制互斥。修改文件不会更新正在运行的 Python 进程，需要用 X 退出旧会话并重新启动。

真机模式会通过 `Astribot(high_control_rights=True)` 尝试获取高优先级控制权，可能从厂商网页/手柄接管。启动前应结束其他运动操作；程序不会自动激活、Home 或配置机器人。启动完成清空旧输入，显示 READY 后的新按键才生效。进程锁与已有 ROS 底盘后端共用，另外扫描现有 tg-chassis 和 ROS 底盘进程；这是尽力检测，不能阻止其他不遵守该锁的程序在之后启动。不要同时运行其他底盘控制程序。

**停车是冻结最后目标，不是立即刹停。** 底盘可能继续收敛到目标；正常退出后保持约 3 秒再释放控制权。失去控制权则不再发送目标。信号、EOF、异常和输入超时都有处理，但强杀、系统卡死、网络缓冲或 SDK 原生调用阻塞无法由此 Python 工具保证停车。现场物理急停必须可用。

启动脚本只加载本地环境，不调用会重写 DDS 配置的 SDK env.sh；不修改系统或 SDK 文件。`--dry-run` 仅用内存假底盘，不加载 SDK，也不申请控制权。启动时应看到 `SDK202_LOCAL`；终端显示 local_cmd 是命令目标，不是实测位姿。

## 测试与现场验收

无硬件测试：

```bash
python3 /home/astribot/TowerGO/workspace/src/astribot_navigation/tests/test_tg_teleop.py
```

自动测试覆盖输入/超时、速度边界、不同 yaw 下 W/S 不改变横向目标、转向后前后移动、控制异常、目标保持、控制权丢失、重复实例，以及真实伪终端中的演练和退出恢复。不会导入真实 SDK 或移动机器人。

现场低速验收：

1. 先运行 `--dry-run`，逐个检查 W/S/A/D/Q/E、空格和 X；确认键盘自动重复适合 0.2 秒续期。
2. 确认机器人已就绪、空间空旷、有人可操作急停，结束其他控制程序。
3. 以 `--linear-speed 0.03 --angular-speed 0.05` 启动真机模式，短按 W/S/A/D/Q/E，确认方向。
4. 检查长按、松手、空格后的实际尾程；必要时降低速度。不同底盘朝向下再次检查 W/S。
5. 检查 A/D 横移、X/Ctrl+C 退出及厂商控制权恢复；记录实测结果。

软件测试通过不能替代实机方向、制动尾程、SDK 环境和控制权交接验收。此次实现不自动执行实机运动。
