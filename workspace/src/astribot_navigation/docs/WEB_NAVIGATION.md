# 在已采集地图上进行网页导航仿真

网页控制离线模拟器，不连接真实 SDK、厂商雷达或底盘。地图使用真实建图导出的 YAML/PGM；实时扫描来自地图射线模拟，不是重放录包。AMCL 使用模拟扫描定位，Nav2 规划并控制模拟机器人。

## 构建与启动（Orin 的 SSH 终端）

```bash
cd /home/astribot/TowerGO/S1_locomotion/workspace/src/astribot_navigation
BASE_IMAGE=public.ecr.aws/docker/library/ros:humble-ros-base bash scripts/container.sh build
bash scripts/container.sh web /data/maps/web_sim_manual_20261021_v4/map.yaml
```

保留终端。电脑另开终端（替换 S1 为自己的 SSH 主机名或 astribot@机器人IP）：

```bash
ssh -N -L 8766:127.0.0.1:8766 S1
```

电脑浏览器打开 `http://127.0.0.1:8766`。

## 使用

1. 点击“设置起点”，在空闲区域按下并拖动指定朝向，点击确认。
2. 等待状态显示“起点已设置，可以选择终点”。此操作放置模拟机器人，并初始化 AMCL；不移动真实机器人。
3. 点击“设置终点”，拖动指定朝向，点击确认开始 Nav2 导航。网页仿真使用 Regulated Pure Pursuit 跟随路径，朝向偏差超过约 7° 时先转向；普通合成实验保留 DWB。
4. 查看估计位姿、真值位姿、两条轨迹、全局/局部路径、速度、剩余路径及动作结果。
5. “停止 / 取消导航”关闭模拟运动许可并取消 Nav2 Action。任务结束后可设置下一目标，或重新设置起点。

滚轮缩放；“拖动查看”平移；“适应地图”恢复全图。绿为估计位姿和轨迹，橙为真值，蓝为全局规划，紫为局部规划。连接中断会标记历史快照。

设置起点后，淡绿色覆盖层按机器人最小宽度标出潜在连通区域。终点应落在覆盖层内，可取消“显示潜在可达区域”查看原图。窄道还需要合适朝向；覆盖层不代替 Nav2 规划和完整矩形碰撞检查。目标所在区域不连通时，页面直接提示“目标不可达，未启动运动”，不会提交运动任务。

页面“导航诊断日志”显示本任务期间收到的 Nav2 警告/错误；终端也会打印起点重设、定位确认、目标提交、目标接受及结束状态。重设起点时清空轨迹，在新位姿和定位确认后才重新记录，避免把位置重设画成穿墙直线。

## 边界

- 网页仿真线速度可设为 0.02–0.30 m/s，角速度不超过 0.1 rad/s；无倒车或横移。
- 地图原点、分辨率和 yaw 均按 YAML 解释；点击坐标为 map 坐标系。
- 模拟机器人保持 0.8 × 0.7 m 轮廓。选点和每步运动均按实际朝向的矩形与所有被覆盖栅格做碰撞检查；额外 padding 为 2 cm。绿色区域按内切圆半径 0.37 m 做必要连通性预检查，不能保证转弯时矩形一定能通过。
- 仅网页仿真配置将 Nav2 的 footprint_padding 设为 0.06 m、inflation_radius 设为 0.60 m、cost_scaling_factor 设为 5.0。规划轮廓比物理碰撞检查多留 4 cm 跟踪余量。普通合成测试保留原参数。膨胀层是路径代价场，并不等于对墙体做同半径的硬扩张。
- 灰色未知区域不可通行；未知会截断模拟射线但不制造障碍回波。已知静态障碍提供模拟激光观测。
- 本工具不能验证真实雷达噪声、三维净空、轮滑、真实制动或地图本身的几何误差；仿真成功不等于真机验收。
- 网页以 10 Hz 续期模拟运动许可，超过 0.5 秒无许可停止模拟运动；关闭网页本身不会终止后端任务，请先点击停止。
- Docker 的 ROS Domain 为 125、ROS discovery 限于容器 localhost。不挂载 SDK 或设备，数据只读挂载。HTTP 通过 bridge 仅映射至宿主机 127.0.0.1:8766，无主机网络或 DDS 端口转发。
- 网页写请求要求会话 token；网页服务只用于本机/SSH 隧道访问。

`Ctrl+C` 退出启动终端。若 SSH 意外中断后容器仍在运行，可用 `sudo docker stop towergo-nav-web` 结束本工具容器。


原图和录包保留。去噪仅对仿真实验：删除最多 3 个栅格的孤立障碍簇，要求每个障碍格的 7×7 邻域无未知格、至少 85% 已知空闲，并距离较大障碍超过 15 cm。不对墙体整体腐蚀，也不填白未知区域。小真实障碍可能符合该规则，派生图不应直接替代真机障碍感知。

## 新圈选修正与低速跟随

最终地图 `/data/maps/web_sim_manual_20261021_v4/map.yaml` 在 v2 基础上继续清除了用户新标记的 216 个障碍格，包括沿墙向通道内突出的标记碎片。每次修改各有 `manual_edits.json` 与局部 `comparison.png`；未知区域保持不变，旧版本均保留。

```bash
bash scripts/container.sh web /data/maps/web_sim_manual_20261021_v4/map.yaml
```

网页专用 `config/web_controller.yaml` 将原局部采样器替换成 Nav2 Regulated Pure Pursuit：目标线速度 0.08 m/s，朝向误差阈值 0.12 rad，原地转向速度 0.1 rad/s，开启矩形碰撞预测及按曲率/障碍距离减速。网页执行端线速度上限为 0.30 m/s、角速度上限为 0.1 rad/s。普通离线实验没有传入该控制器配置时保留 DWB。

网页到点容差为位置 0.15 m、朝向 0.08 rad：留出 AMCL 厘米级波动的空间，避免到点后反复切换追踪路径与最终转向。仍要求最终朝向满足条件才报告成功。

局部和全局代价地图均读取独立 `/sim/collision_map`：启动时在临时目录生成碰撞地图，将未知区视作障碍，由独立 map_server 发布，退出时清理临时目录。原始 `/map` 仍用于 AMCL 和网页，原地图的未知格不被修改。这样使控制器碰撞预测与模拟器的“未知不可通行”规则一致。局部代价地图同时保留静态层与激光障碍层。

网页实时速度取自模拟真值里程计，另行显示控制指令速度。若矩形物理检查阻止运动，后端立即撤销模拟运动许可并取消目标、显示具体原因，不再持续发送无效指令。

开发复测入口 `scripts/validate_web_route.py --port 18766 --start x y yaw --goal x y yaw --seconds 900 --output <新报告路径>` 使用独立测试网页，不允许连接交互会话端口 8766。报告保存位姿、速度、剩余路径、动作结果和诊断；超时会取消任务，不将仅生成路径视为导航通过。测试可传 `web_navigation.launch.py rate:=2.0`，正常网页默认 `rate:=1.0`。

速度保护器超过上限时同步缩放线速度和角速度，保持 v/ω 转弯半径；原来分别截断会扩大弯道半径。网页曲率减速参考半径为 1.0 m，急弯先减速，角速度上限保持 0.1 rad/s。

网页全局规划基于 `SmacPlannerLattice` 和 Humble 自带的 5 cm 差速运动原语，按矩形车身和朝向规划，允许原地转向，不生成倒车扩展。当前配置用于本次分辨率 0.05 m 的地图。保留原始未平滑的运动原语路径，避免平滑将路径推入窄道边界。`ExactGoalLattice` 插件对离散终点到用户精确终点的短距离移动和转向逐步检查碰撞，再追加用户的原始目标，避免最终朝向被离散角度替代。

静态地图仿真使用专用 `web_navigation.xml`：规划后执行同一路径，局部控制持续受阻 5 秒则停车，等待 0.5 秒后重新规划，最多恢复 3 次；不在终点转向期间周期性替换路径，防止反复生成绕圈的末段。未延长原有的 60 秒进度检查。初始化起点时会重发初始位姿，直到 AMCL 确认接收，避免启动阶段订阅尚未建立导致请求丢失。

网页还会检查 `/bt_navigator/get_state` 是否为 Active；仅发现 Action 接口不能视作就绪，否则冷启动时可能提交给尚未激活的服务而被拒绝。

## 导航前设置速度

网页的“前进速度（m/s）”可在提交终点前设置为 0.02–0.30，默认 0.08。
开始导航前必须收到控制器参数服务的成功确认；失败或超时不提交目标。
导航期间输入框锁定，停止并等待任务结束后可为下一任务修改。
该值是期望前进速度，转弯、障碍和末端接近仍自动减速；角速度上限维持 0.1 rad/s。
网页专用仿真上限为 0.30 m/s，普通仿真实验默认上限仍为 0.10 m/s。
