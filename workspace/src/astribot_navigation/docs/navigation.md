# 导航

使用 experiment navigation 加载地图，先验证AMCL初始化收敛，再通过标准NavigateToPose依次执行三个目标。默认NavFn+DWB，速度仅前进和转向。

局部代价地图分别读取前后原始点云并保留观测原点。虚拟scan用于SLAM/AMCL，合成双雷达存在遮挡/自由空间近似，须由对照实验评估。

任务取消使用Action取消接口；不调用整机stop_robot、restart_robot或move_to_home。

DWB外层增加RotationShimController：先对准新路径再跟踪，避免0.3rad/s低角速度下原地转向采样停滞；线速度和角速度上限不变。

使用ObstacleFootprint critic检查矩形完整轮廓，代价地图轮廓额外padding=0.06m，以覆盖栅格和定位误差；碰撞评分仍使用原始0.8×0.7m轮廓。


## 真机网页定位（2026-10-23）

```bash
cd /home/astribot/TowerGO/S1_locomotion/workspace/src/astribot_navigation
bash scripts/tg-navigation.sh --mode observe
```

另一台电脑通过 `ssh -N -L 8767:127.0.0.1:8767 S1B` 转发，打开 http://127.0.0.1:8767；服务重启后按 Ctrl+F5。

观察模式不加载 SDK，也不申请控制权，机器人不会因初始化而移动。先在地图中选择机器人当前真实位置并拖出朝向，再确认初始化。定位前可通过局部扫描及“手动位置预览”核对；初始化后以 AMCL 修正位姿为准，检查黄色扫描是否对齐地图墙面。初始化最多等待 60 秒，只有收到新位姿且协方差及时间检查连续有效才进入就绪。

`/api/state` 的 `ready_checks` 分别提供 TF、AMCL 源时间和接收时间；`pipeline` 提供各阶段耗时、源数据年龄和有界队列状态。扫描转换到最新已测 LIO 姿态，原始观测年龄仍单独用于 0.5 秒健康检查，不能用新的参考时间掩盖旧数据。

本轮静止修复与测试进度见仓库根部 `HANDOFF.md`。观察模式就绪不代表已完成真机移动验收；实际控制入口为 `--mode hardware`，应在静止地图对齐检查完成后由现场操作者启动。真机故障/取消会按执行器逻辑调用整机停止，不自动续走；与本文前部离线实验的取消方式不同。


真机避障恢复：使用真机目录的 `navigation.xml` 周期重规划，规划或跟随失败时等待后重试。等待期间速度指令缺失会立即转成零速，不使用旧速度；只有动作反馈持续更新且定位/传感器/执行器健康才保持等待。真实数据过期、控制权丢失、浏览器失联依旧终止任务。网页诊断和事件日志会记录具体故障检查，而不是仅显示笼统的“失效”。

2026-10-23 用户要求放宽短暂扫描延迟：派生水平 scan 源年龄上限调整为 0.8 s，接收断流仍为 0.5 s，原始雷达/IMU/LIO 仍为 0.5 s。0.5–0.8 s 的扫描标为延迟扫描，API `scan_source_timeout` 可检查运行值。该修改不提高速度、不取消碰撞检测或控制失联停车。

2026-10-23 最新真机参数：配置轮廓保持原值，额外 padding 0.02 m，RPP 碰撞预测 1.5 s，碰撞检测保持开启；浏览器许可为 2 s，SDK 看门狗不变。修改已经通过隔离的真实 RPP 控制器对照：原近前方占用场景恢复 0.05 m/s 输出、更近障碍仍保持零速。实际行走由现场提交新目标验证。

### 当前固定姿态自体过滤

2026-10-23 用户确认近前方约 0.8 m 高的左右侧回波来自机器人自身。真机 navigation.yaml 的 self_filter_boxes 在底盘坐标系过滤两个局部三维盒，仅适用于当前固定收拢姿态。盒外、上方及下方障碍保留，原始雷达和 FAST-LIO 输入不变；改变手臂/上身姿态后需重新核对自体几何，不能扩大屏蔽盒代替外参或真实障碍排查。
