# 底盘目标累积与恢复修复（2026-10-24）

## 已证实的机制
故障会话 navigation_20261024_215150_6e1fd5：目标相对反馈领先 0.1001907329 m、0.0040558787 rad；位置上限 0.1 m 被超过约 0.19 mm。
原 Drive 每次循环在上一个目标上累加速度 × 0.01，不根据跟随差距调节。位置/角度偏差与 >100 ms 调度间隔都抛异常，统一进入 SDK stop_robot 并锁定会话。零速度仍保持未执行完的领先目标。
这些事实解释触发机制，但不能单凭日志判定底盘响应迟缓的硬件原因。

## 改动
- 显式新任务使用新鲜底盘反馈作为积分起点，不继承旧 desired backlog。
- 10 cm / 0.1 rad 保留为目标推进预算，不再作为普通跟踪误差的故障阈值；预算上半段平滑减小推进量，线速度与角速度按同一比例缩放。
- 短时调度延迟仅告警，跳过该周期，不累积错过的时间；过期指令/许可另行取消任务。
- 零速度撤回未执行的目标领先量，向 SDK 请求当前反馈位置保持。
- 导航数据失效、指令或许可过期：取消 task，反馈新鲜且控制权有效时请求位置保持；至少 0.15 秒反馈稳定后允许显式新任务，不自动恢复旧 task。
- 保持请求后 3 秒仍不能确认静止、SDK 反馈无效、控制权丢失、SDK 调用失败仍使用故障停车；显式用户停车和 SDK 已有 stop_robot 锁定不自动清除。
- 到达目标、Nav2 任务结束、定位数据中断和浏览器失联也使用取消任务与静止确认，避免正常任务结束误触发 SDK 永久锁定。
- 页面固定警告区显示跟随降速；指令栏显示执行器实际目标推进速度，不再仅展示规划器请求速度。
- 保持原地图、静态地图避障、速度上限、碰撞轮廓和定位质量判据。

## 验证与限制
首次完整回归 190 passed / 1 skipped；硬件 --check 通过（不构造 SDK、不发运动指令）。
新闭环替身测试覆盖三种响应时间常数各 600 秒模拟运行、底盘阻滞和释放、零速度撤回积压、调度抖动、失效取消、恢复不续走、保持失败、反馈失效、显式停车与非有限值。
替身不是物理模型；反馈位置保持经 SDK filter 通道下发，不能等同于实测制动保证。真实低速跟随和停车仍需用户验收。
现有运行进程不会热更新，需结束旧会话后重新启动。旧 SDK 故障不会自动解除。
