# 双雷达水平切片导航地图

默认启动方式不变，FAST-LIO 仍使用完整双雷达点云和前 IMU 估计位置；网页和主要导出变为二维占据栅格。本功能不启动 Nav2 控制器、不发送自主导航指令。

```bash
ssh -t -L 8765:127.0.0.1:8765 S1 \
  '/home/astribot/TowerGO/workspace/src/astribot_navigation/scripts/tg-mapping.sh'
```

电脑浏览器打开 `http://127.0.0.1:8765`。保持静止初始化，READY 后 W/S 前后、Q/E 转向、空格保持、X 保存退出。校准记录仍只是提示，不新增标定批准开关。

## 高度和坐标

- 默认切片厚度 0.10 m，上下各 0.05 m，中心为首个 LIO 位姿对应的前雷达中心。
- 使用初始化前 100 条有效前 IMU 加速度的均值确定重力方向，在初始静止假设下建立固定水平坐标系；不是把雷达本身的倾斜平面作为水平面，也不假设 `camera_init` 已经重力对齐。
- 切片坐标系原点在前雷达初始中心，地图 XY 为水平面；这里的高度 **不是离地高度**。生成的 `slice.json` 保存从 LIO 世界坐标到切片坐标的旋转和原点。
- 两路原始点已经在前雷达坐标系中，不重复变换后雷达端点。后雷达射线原点来自会话驱动配置的平移，当前约为 (0.001, -0.496, 0.084) m。
- 使用本次 FAST-LIO 的前雷达到 IMU 外参；逐点时间匹配 LIO 位姿，平移线性插值、旋转最短路径 SLERP。位姿间隔超过 0.3 秒或点落在位姿范围外时不外推，舍弃并计数。前后雷达都按共同薄层筛选。
- IMU/LIO 轨迹转换到切片坐标系保存，未将其冒充为底盘中心轨迹。位姿插值是低速场景下的运动近似，不等同于重新运行 FAST-LIO 内部 IMU 积分。

可调整相对初始前雷达中心的高度和厚度：

```bash
./scripts/tg-mapping.sh --slice-offset 0.10 --slice-thickness 0.10
# 如另需三维点云：
./scripts/tg-mapping.sh --export-pcd
```

`--slice-offset` 支持 -0.5 到 2 m；`--slice-thickness` 支持 0.02 到 0.5 m，均拒绝非有限数。默认不导出 PCD，但原始与 LIO 点云录包仍保存。

## 栅格证据与资源

- 分辨率 0.05 m。黑色障碍、白色空闲、灰色未知；地图不预先膨胀。后续 Nav2 根据机器人的碰撞轮廓处理通行宽度。
- 障碍使用所有通过过滤的薄层内回波，按每帧每格去重；至少两个观测帧且证据分数足够才确认。无观测区域始终未知，不填白。
- 空闲证据只来自实际回波射线与薄层相交的部分。两颗雷达使用各自真实原点，射线不延伸到回波背后；过高的射线不清空该层。没有回波或无匹配位姿均不产生自由空间证据。
- 每帧最多均匀选取 1024 条实际射线生成空闲证据，障碍端点不按此上限抽样。沿射线以小于半格间距采样，端点前保留 1.5 格边界。未覆盖的格子保持未知。
- 静态建图采用保守累积：已确认障碍不被后续不同高度射线擦除。因此移动物体可能留下痕迹，应尽量在环境静止时建图；本版不是动态障碍清除系统。
- 距离过滤相对各雷达原点为 0.15–20 m；排除无效回波标签，以及厂商前雷达到底盘变换下的本体 XY 轮廓（网格边界额外加 2 cm，垂直挤出）。相关数值完整快照在 `slice_config.json`，不是新增标定验收门槛。
- 切片独立进程运行，位姿缓存 512 条、待匹配点云 40 帧、轨迹预览 10000 点。二维栅格按需扩展，上限 4,194,304 格；不因范围增长改变 5 cm 分辨率。
- 网页及 `nav_msgs/OccupancyGrid` 约 1 Hz 更新。话题为本次会话前缀下的 `occupancy`，可靠且 transient-local；它与 LIO 输出一起录制。TF 写入隔离会话的 `tf_static`，不覆盖系统 TF。
- 切片进程退出、报错、状态更新停顿超过 3 秒或处理时间戳落后 LIO 超过 2 秒时，由原有会话健康机制撤销遥操心跳。退出仍是冻结目标和收尾，不是物理急停。

## 保存和旧录包转换

新会话正常结束后：

```text
<会话目录>/
  raw_bag/                 原始前后雷达及 IMU
  lio_bag/                 LIO 点云、位姿、实时 OccupancyGrid
  slice_config.json        切片参数和外参快照
  slice_live.json          最后实时预览及处理计数
  slice.log                切片进程日志
  navigation/
    map.yaml               Nav2 map_server 地图描述
    map.pgm                原始占据栅格（不画轨迹）
    preview.png            地图和 IMU 轨迹预览
    trajectory.csv         切片坐标系下完整时间戳与位姿
    slice.json             坐标变换、统计、来源状态与参数
    map.pcd                仅 --export-pcd 时生成，使用同一切片坐标系
```

`map.pgm` 为 P5 格式：0 障碍、254 空闲、205 未知；图片从上向下保存，OccupancyGrid 从地图最低 Y 向上排列。YAML 原点是最低 XY 栅格角，yaw=0。最终地图从保存的原始点和 LIO 位姿重新计算，不受网页丢帧影响。

已有会话（包括原三维会话）可重新生成地图，无需启动 ROS 节点、雷达或 SDK：

```bash
./scripts/tg-mapping.sh finalize /绝对路径/旧会话目录
./scripts/tg-mapping.sh finalize /绝对路径/旧会话目录 \
  --slice-offset 0.10 --slice-thickness 0.10 --export-pcd \
  --output-directory /绝对路径/新的结果目录
```

默认生成 `navigation_<时间>_<随机编号>/`，保留旧产品；指定目录已存在则拒绝覆盖。新会话恢复默认继承快照参数，旧会话默认 0 偏移、10 cm 厚度。转换需要原始前后雷达/前 IMU、LIO 位姿及已保存外参配置；仅剩旧 PCD 不能恢复可信射线自由空间。结果无已确认障碍或无空闲格时明确报错，不标记成功。恢复不会更改原 incomplete 状态。

## 验证与边界

无硬件单元测试：`python3 tests/test_mapping_slice.py`。验证不同高度和倾斜、重力对齐、运动位姿插值、真实后雷达原点、未知区域、自身过滤、证据积累及文件行方向。原有遥操和建图回归测试继续保留。

离线真实 SLAM 回放沿用 `--replay`，隔离 Domain 125 / localhost。Nav2 文件加载验证可在已加载 `/opt/ros/humble/setup.bash` 且同样隔离的终端运行 `python3 tests/validate_slice_nav2.py <navigation目录>`；只创建 map_server 和验证订阅，不启动导航控制器。

单一薄层无法表示层外矮障碍或悬空物；未来导航仍需要全高度实时避障、底盘位姿接入和整机碰撞轮廓。本次未新增回环优化；二维输出不会消除 FAST-LIO 的长距离漂移。现场效果尚需操作者低速行驶、观察地图并 X 退出确认。
