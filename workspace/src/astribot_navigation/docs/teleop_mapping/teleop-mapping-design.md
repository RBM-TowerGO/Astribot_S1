## 结论

可以采用手柄人工驾驶、雷达持续采集、SLAM 估计位姿并生成地图的方式。人工驾驶阶段不需要 Nav2 控制底盘。当前传感器采集和离线软件基础已经具备，但手柄接入、可靠停车、真实位姿来源尚未完成实机验证，因此不是直接启动现有离线 launch 就能完成的功能。

首轮建议：复用经现场确认可靠的厂商遥控链路，只读录制移动数据，再在隔离容器离线建图；验证成功后增加实时地图显示。本次仅研究和读取状态，没有启动遥控、申请控制权或发送运动指令。

## 推荐架构

控制支路：手柄 → 厂商手柄节点 → 唯一、经过验证的遥控控制程序 → 底盘。

数据支路：雷达、IMU、实测状态 → 只读录包 → 位姿估计与点云处理 → SLAM → 地图保存。

两条支路只共享观测数据。SLAM 不需要控制权，也不应该向底盘发送命令。手动建图时不运行 Nav2 的导航控制器。ROS 的 teleop_twist_joy 只将 Joy 转为 Twist，不会自动解决 Astribot 的底盘位置控制适配、断连停车或控制权管理；其标准启动文件还会启动 joy 节点，不能与厂商驱动重复启动。[Humble 文档](https://github.com/ros2/teleop_twist_joy/blob/humble/README.md)

### 路线 A：验证实测底盘里程计后沿用二维建图

只读订阅真实底盘反馈，确认单位、轴方向、参考坐标系、时间戳、复位规则和更新频率；然后转换为 `/odom` 和 `odom → base_link`。不能使用 desired position，不能用手柄速度积分冒充测量，也不能用恒等 TF 掩盖缺失的里程计。

雷达点云完成时间检查、必要的运动去畸变、车体过滤和高度切片后产生 `/scan`。SLAM Toolbox 需要扫描及有效的 odom_frame 到 base_frame 变换；建图时由其独占发布 `map → odom`。[Humble 接口文档](https://github.com/SteveMacenski/slam_toolbox/tree/humble#api)

静态传感器 TF 必须来自真实安装关系，不能沿用模拟的 x=±0.30 m。原始点云已应用的外参不能重复施加。建图阶段不同时启动 AMCL 发布同一条 map → odom。[ROS 坐标系约定](https://github.com/ros-infrastructure/rep/blob/master/rep-0105.rst)

### 路线 B：底盘里程计不可用时采用激光惯性里程计

先使用前雷达和前 IMU 做 LIO，产生连续运动估计。可评估 Ericsii/FAST_LIO_ROS2 的 **ros2 分支**；该分支推荐 Humble，并有 MID360 配置。这是候选开源适配方案，本机尚未构建和验证，不能视为厂商支持的即装即用模块。[ROS2 项目](https://github.com/Ericsii/FAST_LIO_ROS2/tree/ros2) · [MID360 配置](https://github.com/Ericsii/FAST_LIO_ROS2/blob/ros2/config/mid360.yaml)

接入前必须核验：

- 现有 PointCloud2 虽有 timestamp 字段，但仍需确认每点时间的单位、绝对/相对时间、与帧时间关系，以及算法实际接收的消息类型。不能只改字段名字就认定完成适配。
- 静止录包的加速度模长约为 1，提示可能使用 g；需要结合驱动和算法实现确认转换位置，避免漏乘或重复乘 9.81。
- 前后点云均标为 livox_frame，不能由此推断 IMU 也处于相同坐标系。核验 LiDAR–IMU 外参及驱动对点云、IMU 分别做了什么变换。
- 先做单雷达基线；不能直接混合两路 IMU 或把双雷达拼接后当成一个未经适配的 LIO 传感器。
- LIO 输出坐标系到 base_link 的转换需要真实外参；与二维 SLAM 联用时只让 LIO 提供连续 odom，SLAM 提供 map 修正，避免重复 TF。不能仅凭 FAST-LIO 累积点云宣称已有完整全局回环能力。

## 分阶段操作

1. **手柄只读识别。** 接收器接入机器人，读取设备与 Joy 消息，确认轴、按键、消息频率、连接状态和心跳。先不启动新底盘控制程序。现有 xbox_controller 订阅者的所属进程和作用要查清。
2. **确认遥控控制与停车。** 优先复用厂商经过验证的操作入口。若必须开发 SDK 适配器，应在工作区单独实现，不改厂商 SDK；加入按住才允许运动、死区、有限值检查、轴长度检查、命令限幅、消息新鲜度和独立连接状态检查。单纯重复发布旧 Joy 的 autorepeat 不能证明手柄仍连接。停止积分位置目标也不等于已经证明物理停车，需核验控制器跟随误差和厂商停止语义。
3. **短距离位姿验证。** 在现场操作者确认遥控和急停有效后，未来试验由人驾驶做短距离前进与转向，检查反馈是否符合实际米、弧度及参考系。先记录，再决定路线 A 或 B。本次没有执行这些运动。
4. **小范围闭环录包。** 建议初始速度 0.1–0.2 m/s、角速度 0.2–0.3 rad/s，禁用横移和加速模式；起止各静止数秒，缓慢绕行并回到起点。保持雷达与底盘的安装关系固定，记录一次 2–3 分钟数据后检查质量。
5. **离线重建。** 前雷达先建图，再评估后雷达对覆盖与重影的影响。检查轨迹连续性、回到起点的错位、墙面厚度、门洞形状、未知区和时间同步；没有真实轨迹基准时不得声称通过仿真的 RMSE 指标。
6. **保存与复用。** 保存原始 bag、驱动配置、外参、版本、轨迹、地图 PGM/YAML 及 SLAM 序列化状态。加载地图检查无误后，再开发在线查看地图入口，最后另行开展定位和导航。

## 录制与回放边界

录制前后点云、前后 IMU、实际发布的底盘测量状态、有效 odom、TF 和 TF_static；可附加 Joy/连接状态用于故障分析。记录原始时间戳，不在采集阶段伪造真实里程计。

主机只读采集沿用实机 ROS_DOMAIN_ID=25。离线回放在现有隔离容器、独立网络和 ROS_DOMAIN_ID=125 中进行。使用明确的话题白名单，禁止把 Joy、底盘命令或控制权相关数据回放到实机域。Domain ID 只是发现隔离手段，不是权限控制或安全认证。

实时建图应另行设计只传观测数据的桥接与 TF 所有权，不能直接把整个离线模拟系统接入实机网络。在线使用真实时间；录包回放使用录包时钟并统一 use_sim_time。

此前的 `scripts/build_static_map.py` 假设机器人静止，不能处理移动录包。此前静止地图也不能证明移动 SLAM 已经验证。
