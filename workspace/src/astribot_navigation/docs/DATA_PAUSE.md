# 短时扫描 / TF 超时暂停恢复

按用户 2026-10-24 确认，覆盖此前“所有数据恢复均不续走”的规则，仅对运行中扫描 / TF 过期开放原目标恢复。不改变任何源数据、接收时效、定位或速度阈值。

运行中扫描 / TF 过期且其他条件正常，撤销旧 Nav2 动作并发送现有 cancel_stationary 保持请求；保留浏览器租约和目标。等待期间不向执行器发送非零指令。旧动作回调按动作代次失效，旧动作结果到达后才允许恢复。

扫描、TF、AMCL 更新、地图质量、SDK 静止与保持完成、旧动作结束等条件连续满足 2 秒后，创建新任务编号，从当前位姿重新规划原目标。任一条件中断重新计时；暂停总期限始终为 10 秒。超时取消，需手动重提。

手动停止、浏览器失联、定位失配、原始传感器失效、历史中断、执行器反馈过期/故障、失去控制权、生命周期异常均取消自动恢复。执行器仍使用现有反馈超时保护，绝不清除 SDK 故障。恢复定位事务不恢复导航。

/api/state 新增 data_pause：elapsed、healthy_seconds、timeout=10、recovery_seconds=2；phase=paused。页面沿用固定警告区及状态栏，不移动按钮。暂停时隐藏执行器泛化的“请重新提交”告警，显示本次等待规则。

隔离测试覆盖连续 2 秒、反复过期、绝对 10 秒超时、动作取消确认、静止/保持条件、其他故障拒绝恢复、浏览器失联和停止清理。硬件 --check 不创建 SDK。代码需重启服务加载；未执行真机运动，实际停车及自动重新规划待用户现场验收。
