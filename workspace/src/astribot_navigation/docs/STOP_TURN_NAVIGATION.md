# 折线直行与停车原地转向

**历史方案：2026-10-29用户已允许边走边转，当前真机默认已切换连续曲线跟随，见 CONTINUOUS_NAVIGATION.md。下文保留实现与历史验证。**

## 行为

真机/隔离录包导航改为：规划经过碰撞检查的折线 → 原地对准第一段 → 确认静止 → 直线行驶 → 转折点停车确认 → 原地对准下一段 → 继续直行 → 终点停车后调整用户朝向。

新增 `towergo::StopTurnPlanner`、`towergo::StopTurnController` 和 `towergo::StopTurnGoalChecker`。真机入口 `session.nav_params` 成套选择这三个插件，不再使用旧的曲线 lattice/RPP 组合；旧插件及通用仿真配置保留。不是仅关闭平滑，也不会在折线失败后回退到曲线。

- 规划器优先直接连接。需要绕障时，用二维 A* 获取通道，再用全轮廓直行/原地旋转检查简化成少量转折点。A* 的内切圆只是生成候选通道，不能直接执行；最终每条边均检查完整矩形。只有实际转折检查所需角度，不要求沿途所有位置都有整圈旋转空间。
- 碰撞检查涵盖轮廓边界和内部占用格，未知区域、地图之外都拒绝。规划额外留 5 cm 跟踪余量；地图原文件、0.2 m 膨胀配置、实际碰撞轮廓与其原有 padding 不变。控制时仍检查当前位置的实际旋转扫掠和直行预测。
- 路径保留明确转折点，不用平滑器把转折磨成弧线。行为树改为先规划、后跟随，行进中不再每秒替换路径。跟随失败后停车等待再规划；既有短时数据暂停恢复仍发起新动作，从当前位置重新规划。
- 直行只输出线速度，转向只输出角速度。转向前和转向结束后均先输出零速度，使用现有执行器“撤回目标超前量”的处理。
- 进入下一阶段必须收到新鲜 SDK 反馈：控制权有效、无故障、任务存在、没有执行器保持事务；SDK `stationary=true` 且实际应用命令为零持续至少 0.2 秒，同时本次等待阶段至少 0.25 秒。不是仅靠计时器认定停稳，也不依赖带抖动的 LIO 速度判断静止。
- 中间转折点到点范围 5 cm；初始对准误差 0.01 rad。真正偏离直线超过 3 cm，或朝向偏差较大时，先停下再重新对准，不能边走边修正成弧线。3 cm 是重新对准的触发值，不是锁死会话的阈值。
- 保留终点 0.15 m / 0.08 rad 验收容差，默认速度 0.05 m/s、最高 0.30 m/s、角速度最高 0.1 rad/s。前进与转向加速均限为 0.1（相应单位）；零速度请求停车可以立即发出。
- `route_execution` 话题和 `/api/state.route_execution` 展示当前段、停车确认、直行、原地转向及终点调整阶段。网页沿用固定高度信息区域，按钮不会随状态变化移动。

## 生效与边界

已编译安装。已启动的旧进程不会热切换插件，需要重新启动现有导航入口并刷新网页。没有接管控制权、启动硬件导航或恢复旧目标。真正的停车效果、转折点跟踪和低速实机运行仍由用户验收。

仍只使用已有二维地图，不增加实时障碍层。规划器允许直穿窄通道，但如果必须转向的位置确实没有完整轮廓所需的旋转空间，会拒绝该路径，不以曲线偷偷替代。有限时间 A* 与可见性简化不保证找到所有理论可行路径；失败后保留停止和重新规划行为。

收尾只读检查：8767 API 未运行，未发现真实 `real_navigation.session` 进程；本轮没有主动停止或启动该硬件进程。下次沿用现有启动命令即可加载新逻辑。

2026-10-29更新：直行轻微偏离3 cm/0.08 rad需连续0.3秒再停车重新对准，短暂正常会清零；大偏离10 cm/0.25 rad及朝向背离目标仍立即停车，逐指令碰撞扫掠不变。意在避免瞬时位姿噪声触发反复对准，实机效果待验证。

## 2026-10-29 并行重规划

真机行为树改为 PipelineSequence + 1 Hz RateController：规划计算期间继续跟随当前有效路径，移除原来的串行 Plan→Follow 和失败后固定 Wait 1秒循环。规划/控制实际失败仍终止动作，不在无路径或控制失效时伪造非零速度。

StopTurnController 收到相同终点/朝向、相同下一转折点且坐标系一致的新路径时，保留当前段、转向/直行状态、速度和计时，不因每次重规划重新进入停车。下一转折点或终点真实改变仍重新确认，保持现有转角/终点停车规则。连续小速度不能代替停车确认。此实现只消除兼容路径更新的强制停车，不是“全程非零速度保证”。
