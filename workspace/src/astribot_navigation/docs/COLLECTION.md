# SLAM 与 VLM 联合采集

默认方式：**实时 FAST-LIO 建图 + 原始数据归档，结束后离线导出**。复用现有地图网页，驾驶仍在 SSH 终端。采集时不运行 VLM，不启动自主导航。

## 启动

先在旧遥操终端按 X 退出；不能同时启动两个控制者。在电脑终端执行：

```bash
ssh -o ServerAliveInterval=30 -o ServerAliveCountMax=6 -t -L 8765:127.0.0.1:8765 S1 \
  '/home/astribot/TowerGO/workspace/src/astribot_navigation/scripts/tg-mapping.sh --linear-speed 0.03 --angular-speed 0.10 --torso-speed 0.02 --task "从起点走到门口并观察周围"'
```

浏览器打开 **http://127.0.0.1:8765**。这是 TowerGO 采集网页，与厂商 5141 控制页面不同。

启动时复用已运行的传感器。全部相机未发布时，通过厂商相机服务请求开启；部分相机缺失时不重启共享驱动，而是等待并报告缺失。雷达沿用既有启动流程。不修改厂商相机配置，不初始化 SDK 来读取传感器。

保持静止等待 READY：雷达/LIO 初始化及五个相机的 RGB、深度（双目无深度）、尺寸元数据和头/躯干/底盘反馈实际写入后，才进入遥操。相机启动可能需要数秒。60 秒未就绪则保存失败原因，不开始驾驶。

- W/S 前后，A/D 横移，Q/E 转向，R/F 腰部升降；H/P 仍沿用长按姿态操作。
- 网页查看地图、数据新鲜度及录制载荷量；五个相机预览默认关闭，可勾选启用；可以填写任务、标记事件。没有运动 HTTP API。
- 空格保持目标；X 正常结束。先完成遥操收尾，保留传感器尾段，再关闭录包和导出地图。
- 保持目标可能存在收敛尾程，不等于立即刹停。进入人工遥操后，地图延迟、传感器缺失和采集故障只警告，不撤销键盘会话；磁盘低于 3 GiB 时只停止录制，不自动重启，保留不完整记录。启动仍需数据就绪；控制权丢失、SDK 通信失败、控制循环失效以及 SSH/会话终止仍执行停止发送和释放控制权。
- 只有本会话开启的相机/雷达才尝试关闭；外部订阅者仍在使用时保持开启并记录。相机压缩驱动自身订阅不视为外部使用者。服务超时结果视为未知，不反复开关。

仅需原有雷达建图时加 `--mapping-only`。旧 `--replay` 保持离线模式，不启动相机、雷达服务或 SDK。

## 保存内容

默认会话目录为 `workspace/data/mapping/mapping_<时间>_<编号>/`。该目录目前通过已有软链接落到 `/home/astribot/Glass Semantic Knowledge/data/mapping`；终端输出实际路径。也可用 `--output-root` 指定新的数据根目录。

| 文件/目录 | 内容 |
|---|---|
| `raw_bag/` | 前后雷达与两路雷达 IMU，沿用原入口 |
| `sensor_bag/` | 五个相机的 RGB、四路原始深度及对应元数据；发现的灰度/相机信息流也归档；头、躯干、底盘、双臂和夹爪反馈；底盘 IMU；有数据的 TF/力接口 |
| `lio_bag/`、`navigation/` | LIO 位姿、配准点云、栅格以及导出的二维地图/轨迹 |
| `teleop.jsonl` | 收到的按键批次、速度设置、成功返回的底盘/腰部 SDK 目标发送、姿态调用、控制权变化、退出和错误 |
| `task.json`、`annotations.jsonl` | 初始任务及带接收时间的任务修改/事件标记 |
| `collection_live.json`、`collection_report.json` | 已写消息数、来源类型、时间戳异常、最大观察间隔、缺失与状态 |
| `collection_config.json`、`snapshots/` | 采集清单/QoS、相机标定、URDF（不复制网格）、脚本副本与哈希；雷达参数和外参沿用会话快照 |
| `session.json`、`runtime_warnings.json` | 整轮状态、版本、进程、警告/恢复及错误；失败记录保留 |

腕部和双目现在属于**归档必需数据**；导航模型默认输入仍为头部/躯干。双臂/夹爪、底盘 IMU、TF、力接口为可用则录，缺失显示在报告中。没有自动开启麦克风录音，不能声称未发布的传感器已采集。

原始图像按发布频率保存，网页相机预览默认关闭；启用后约 5 秒刷新一次，后台预览文件每 2 秒更新。MCAP 时间为录制端接收墙钟时间，原消息 Header 保留；无 Header 数据明确只能按接收时间关联。软件关联不是硬件同步。报告的间隔/时间戳异常不能当作精确 DDS 丢包率。

深度保留原始载荷；不自动转换成米。底盘局部累计目标、实测关节反馈和 LIO/IMU 位姿分别记录，不能互相当作同一种位姿。

## 离线导出

在 S1 上执行，将末尾路径替换为终端显示的会话目录：

```bash
/home/astribot/TowerGO/workspace/src/astribot_navigation/scripts/tg-export.sh \
  /绝对路径/mapping_本次会话 --interval 1
```

每个相机默认每秒抽取一张 RGB。使用 `--interval` 调整抽帧间隔，`--max-time-difference` 调整允许的关联时间差（默认 0.15 秒）。导出不会连接 SDK 或创建 ROS 节点，不覆盖已有目录。

结果写入新的 `vlm_export_<时间>/`：

- 各相机 JPEG；与 RGB 时间邻近的原始深度。已确认 uint16 布局时另存无损深度 PNG，数值仍是原始单位。
- `frames.jsonl`：图像路径、尺寸、任务描述、源/接收时间、关节反馈、LIO 位姿、每项时间差及缺失项。双目保留左右拼接原图。
- 原始任务/遥操事件日志、配置快照和 `export_report.json`。可从每张图的接收时间关联 `teleop.jsonl`；累计目标不是机器人实测轨迹。

若来源是 incomplete 会话，导出报告继续保留源状态；能抽出图片不等于整轮采集合格。原始数据不进 Git、不自动上传。

## 稳定性修复（2026-10-12）

此前 `mapping_20261012_224244_ff0720` 因切片延迟阈值触发整体退出，原故障和约 38.54 GB 数据保留。现在人工控制与采集健康分开：心跳由独立线程发送，后台计算/录包降低 CPU 和 I/O 调度优先级，终端状态输出遇到拥塞丢弃本次刷新，不阻塞控制。预览暂停不影响原始相机归档。
