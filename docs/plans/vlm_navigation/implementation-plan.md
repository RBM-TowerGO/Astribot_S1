# 实施计划：Qwen3.5-4B 底盘导航

更新日期：2026-10-12\
状态：P0、P1 完成；P2 按用户调整后的传感器与 SDK 核查范围完成；P3 为下一步，P3–P6 未开始。\
最终目标：中文指令驱动的室内目标导航，具备视觉目标确认、几何定位、路径执行、取消和异常停止处理。

## P0：建立方案与现状记录（已完成）

- 确认工作分支及首选模型。
- 记录 S1 硬件、默认 Python 环境问题及已有建图/遥操边界。
- 建立本目录的计划、设计、任务、验收和 taskmemory 文档。

完成条件：文档存在、交叉链接有效，已核实事实与计划明确区分。

## P1：独立推理环境与单图基线（已完成）

工作：
1. 检查 Jetson 环境、已有容器/虚拟环境、CUDA 库路径和模型缓存，确定独立部署位置。
2. 若采用 PyTorch/Transformers，先排查 `libcusparseLt.so.0` 缺失，并核对 torch/torchvision 兼容性。已在隔离 TowerGO 环境中补齐库并完成匹配版本编译与运行验证。
3. 选择支持 Qwen3.5 视觉输入及关闭思考的 Jetson 可用后端；比较维护成本后固定一种，避免同时展开多个部署方案。
4. 下载官方模型，记录 revision、精度、依赖版本和启动配置。
5. 用 FP16 建立效果基线；首轮单图、batch=1、关闭思考、短上下文及有限输出。
6. 若后端 FP16 支持存在阻碍，记录原因和替代精度，不能把量化结果写成 FP16 基线。

建议起始参数（实验配置，非性能承诺）：
- 图像按比例缩放，长边约 640–768 像素；根据模型处理器规则设置像素预算。
- 上下文预算 4096–8192 tokens；输入超限明确拒绝，不静默截断关键指令。
- 输出最多约 128 tokens，采用最小结构化目标；截断或解析失败不进入运动链路。
- 关闭思考需使用后端支持的实际开关，并验证输出，不能只靠提示词要求。

交付物：可复现推理入口、环境清单、单图样例、首轮性能报告。\
完成条件：视觉输入真实生效，结构化输出可解析，重复运行成功；尚不连接底盘。

完成证据：[P1 基线](../../../vlm_navigation/reports/p1-20261010T134757.059795Z/baseline.md)，3 次独立进程启动、5 次预热和 100 次正式请求通过。用户确认只测新进程启动，不重启或清缓存；冷缓存启动未测。完整请求 P50/P95 为 1.819/1.889 秒，适用范围仅为所述两张合成图。

不再以固定数量的图片、人工标注集或模型评估阈值作为当前 P2 完成条件；这些项目未执行，也不记为已通过。

已完成：

- 盘点双雷达、雷达 IMU、底盘 IMU、关节反馈、音频与力接口，区分数据可读、接口存在和未验证。
- 导入 SDK，避开申请控制权的构造函数，实际验证相机读取及雷达启停方法；收到前后点云和 IMU。
- 记录相机状态误报、灰度话题、回调共享配置等 SDK 限制；保留标定/TF/深度单位待核验项。
- 保存原始检查记录与可复用入口，确认雷达恢复原关闭状态，相机保持开启；未执行运动。

交付物：[传感器与 SDK 核查报告](../../../vlm_navigation/reports/p2-sdk-20261010T144531.746622Z/sensor-sdk-audit.md)、观测采集及 SDK 核查脚本。
完成条件：传感器与读取接口的可用性有实际证据，不把未核验的测距、标定或定位记为可用。
下一步先完成 P3 遥操与采集，再在 P4 接入真实图像与 VLM；进入几何导航前补齐坐标与深度链路。

## P3：底盘遥操完善与 VLM 数据采集（下一步，最小实现）

目标：用现有键盘遥操驾驶底盘，录下后续 VLM 所需数据，并能离线读取。

1. 复用 `tg-teleop` 和 `tg-mapping`，修复影响驾驶、退出及保存的实际问题；保留历史失败记录，不重做控制框架。
2. 保留 W/S 前后、A/D 横移、Q/E 转向、空格保持、X 退出；按用户最新要求加入横移，不新增网页遥操。默认线速度 0.05 m/s、角速度 0.10 rad/s，上限分别为 1.0 m/s、0.25 rad/s。
3. 在同一采集会话增加头部/躯干 RGB 与深度、关节反馈、按键及实际发送的局部累计目标；复用双雷达、前 IMU 与 LIO 录包，后 IMU 有数据时记录。附任务描述、时间戳和配置快照，排除腕部相机，双目仅备用。
4. 每次保存到独立目录，保留原始录包、事件日志和简单索引；提供离线抽帧与按时间关联，供 VLM 后续读取。原始数据不进 Git，不自动上传。
5. 做必要的按键/退出检查、现场低速操作确认和录包读取检查；正常会话能保存，失败会话保留原因即可，不建立额外评测体系。

采集与控制分进程；录制就绪后再驾驶，必需数据或录制中断、磁盘不足时结束本轮并保存不完整记录。保持目标不等于立即刹停，须现场确认实际尾程；控制权丢失后不继续发送。时间关联不代表硬件同步，原始深度、局部目标和 LIO 位姿不冒充已标定距离或底盘实测位姿。

交付物：可用的遥操采集入口、简短操作说明、可读取的会话数据和离线图像索引。
完成条件：能低速前后/转向、停止并正常退出；联合数据可读、图像可解码、事件可关联；失败记录可保留。未完成现场确认则如实标记未验收。

本阶段不运行在线 VLM 控制，不做自主导航、模型对比、量化、性能基准、大规模测试或固定数量标注采集。

## P4：目标接口与无运动演练

工作：
- 实现 VLM 服务、严格输出校验、目标解析与任务状态机。
- 优先采用几何模块生成候选可达点、VLM 选择候选 ID 的方式；必要时先输出目标框再由几何模块生成候选点。
- 在固定地图/录包或模拟环境中演练目标选择、取消、过期观测、模型超时和目标丢失。
- 定义 goal_id、观测时间、有效期、坐标系及取消语义；不缓存积压的运动决策。
- 日志能够追溯输入图像、模型输出、接受/拒绝原因和导航状态。

交付物：端到端 dry-run，输出导航目标或拒绝原因。\
完成条件：默认无运动，异常路径不产生新的运动目标；无需加载真实 SDK 即可测试。

## P5：几何导航与底盘适配

工作：
- 验证深度/雷达目标投影、标定、TF 和底盘位姿。
- 在现有 FAST-LIO/切片地图基础上接入定位、地图、规划与控制；Nav2 是计划候选，尚未认定真机链路可直接使用。
- 补全覆盖机器人实际轮廓的实时障碍处理；单一高度薄层不能承担全部避障。
- 明确从导航控制量到厂商底盘局部累计目标的转换，核对方向、单位、时序和控制权。
- 实现控制仲裁、目标有效期、传感器健康检查及取消/停止接口。
- 同时运行 SLAM 和 VLM，测量定位时效、资源竞争及端到端延迟。

交付物：模拟/离线验证通过的导航适配层与控制约束报告。\
完成条件：坐标、控制和停止语义有证据支撑；代码测试不能替代实车验收。

## P6：受控现场验证与交付

- 在适合测试的场地分步核验方向、取消、目标保持的实际尾程和控制权交接。
- 先验证单段低速移动，再验证可见目标导航，最后增加遮挡、多目标和动态障碍。
- 实际速度、运动步长、重规划频率及超时根据现场停止距离与 P95 延迟确定，不预先宣称达到固定导航频率。
- 按 [acceptance-checklist.md](acceptance-checklist.md) 留存结果，失败项保持未通过。
- 完善部署/操作说明、已知限制、复现报告与回退方式。

交付物：可复现部署、使用文档、现场验收报告。\
完成条件：约定场景达到已冻结验收阈值，所有必须异常用例通过，未验证范围明确列出。
