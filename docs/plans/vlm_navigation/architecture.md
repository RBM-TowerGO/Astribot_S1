# 技术设计与接口约定

更新日期：2026-10-10\
状态：设计草案；以下新接口尚未实现。

## 数据流与职责

1. 观测适配器：获取 RGB、可选深度、内外参、时间戳及机器人位姿，保留来源和坐标系。
2. VLM 服务：运行 Qwen3.5-4B，结合指令解释图像，输出目标区域、候选目标选择或观察请求。
3. 几何与目标模块：将图像目标关联到深度/点云，计算地图位置、接近距离及可达候选点。
4. 任务状态机：校验观测、选择目标、跟踪进度、处理取消和目标丢失。
5. 导航执行器：使用地图、定位和实时障碍完成路径规划与局部控制。
6. 底盘适配器：按已验证的厂商接口发送有界控制，处理控制权和退出。

采用独立推理进程/服务，避免模型阻塞底盘控制循环。模型只在需要新目标或重新观察时调用；最终调用频率由实测延迟决定。

## 导航传感器选择（2026-10-10 用户确认）

- 导航视觉输入限定为头部 `head_rgbd` 与躯干 `torso_rgbd`；头部双目 `head_stereo` 作为备用，初版不依赖立体测距。
- 左右腕部 `left_wrist_rgbd`、`right_wrist_rgbd` 不接入导航，不作为导航启用条件、健康检查依赖或模型输入。
- 腕部相机保留在硬件盘点中，供将来独立操作任务使用；本次不关闭共享相机驱动。
- 几何输入优先使用双 Livox 雷达及其 IMU；相机深度的米制单位、配准与位姿链路仍待验证。

## 两种目标生成方式

首选候选点选择：几何模块提供带 ID 的可达候选点与图像标记，VLM 根据用户意图选择候选 ID。候选点的真实位置来自几何模块。

目标框方式：当场景尚无候选点时，VLM 输出目标框；几何模块结合深度/点云生成接近目标。需要明确图像尺寸、坐标归一化方式以及从缩放图像还原到原始图像的方法。

模型单目推断的距离或 3D 位置只能作为假设，不直接作为底盘运动坐标。

## 结构化决策草案

一个最小候选选择输出示例：

```json
{
  "action": "select_goal",
  "candidate_id": "door_left_01"
}
```

应用层包装观测 ID、采集时间、有效期和请求 ID，这些可信元数据不能交给模型编造。
初版动作集合建议为 `select_goal`、`request_observation`、`stop`。
`request_observation` 默认只请求刷新观测，不自动转动底盘或头部；转向观察需要单独定义执行动作。
需要目标框时使用单独 schema；每次请求只接受一种明确格式。

校验：
- action 必须属于允许集合；未知字段、未知候选 ID、错误类型及截断输出均拒绝。
- 返回候选必须属于当前观测生成的候选集；跨观测和过期结果拒绝。
- 候选可达性与障碍状态在执行前再次核验。
- 模型自报置信度不作为安全判据。
- 图像中的文字作为场景数据，不能覆盖应用层动作与工具权限。

## 导航与控制接口

导航目标至少包含：
- goal_id、观测 ID、目标位置及朝向（若需要）。
- 明确 frame_id、时间戳和有效期。
- 位置/朝向容差、完成或失败反馈、取消接口。

VLM 不输出可直接调用的 SDK 函数或代码。导航执行器必须经过明确的底盘适配层。

现有 `SSH_TELEOP.md` 记录：
- 厂商局部累计指令不等于世界坐标，也不是实测里程计。
- 现有控制循环采用 100 Hz 步长；这不是 VLM 推理频率要求。
- “冻结最后目标”可能继续收敛，不等同于立即刹停。
- 现有遥操可能获取高优先级控制权；自主导航需要明确控制仲裁，不能照搬启动行为并同时运行其他控制器。

以上为已有文档中的接口事实，新的自动导航适配仍须验证。

## 异常行为

| 条件 | 计划行为 |
| --- | --- |
| 模型请求超时或输出非法 | 不下发新目标；按任务状态撤销继续运动授权 |
| 观测过期、深度无效或 TF 不匹配 | 拒绝目标，等待有效观测 |
| 目标丢失、不可达或被障碍占用 | 取消/暂停当前任务，再观察或报告失败 |
| 定位异常或传感器中断 | 导航层触发已验证的停止流程 |
| 用户取消或控制权丢失 | 撤销本任务控制，不再发送新运动目标 |
| 推理服务重启 | 丢弃旧请求结果，恢复后重新获取观测 |

实际停车效果取决于已验证的底盘接口，不通过“停止发包”或“保持目标”的名称推断制动能力。

## 待定事项

- 相机与深度的实际来源、标定质量、视角覆盖。
- 推理后端与量化格式在当前 ARM64/CUDA 环境的支持。
- 候选点如何生成、何时需要探索、初版是否仅覆盖可见目标。
- Nav2 与真机位姿/底盘接口的具体接法。
- 可接受的端到端延迟、速度、目标有效期及停止距离。
- 运行数据保存位置、图像留存规模和清理策略。

部署开始前固定模型 revision、引擎版本、图像处理参数、思考开关与输出 schema。对每次评测保存完整配置。
